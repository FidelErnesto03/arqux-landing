The task

One project. Many agents. Unified governance.

Define your project with an AI agent. Switch agents or tools, and the work continues with the objectives, guidelines and context of your project. With each task, that context can grow with new decisions and learnings.

  1. 01DefineAdd password recovery. Condition: do not modify the existing authentication.

    condition · acceptance

  2. 02WorkAgent A checks the condition, proposes the solution, implements the link delivery and records decisions, evidence and a checkpoint.

    condition · context · evidence

  3. 03ResumeAgent B receives the progress and the same condition, then completes the link validation.

    progress · condition · session

  4. 04Review and learnYou check the result against the conditions and review the tests. Relevant decisions and learnings can be carried into future tasks.

    condition · tests · learning

Quickstart

Three commands, one directory.

No server and no API key. Install, initialize a governed workspace, then render its files for each agent app. Your guidelines and context stay in plain, portable files.

Terminal
$ pip install arqux
$ arqux init
$ arqux sync-harnesses
$ pip install arqux
$ arqux quickstart
$ arqux sync-harnesses

Both routes ship in v1.0.0: init initializes the workspace; quickstart runs the interactive onboarding for a new agent. Confirm behavior against the release you install.

Codec‑CORTEX

Every line is one idea.

CORTEX is the mandatory memory format of ArqUX v1.0.0: dense for machines, readable as HCORTEX for people, and validated with loss==0 before every write.

One idea, two surfaces, one source — type and both renderings update. The real codec validates with loss==0; this demo shows the pairing only.

Signal, not filler

One idea per line

Norms live in typed ideas, not in prose. Density is a property of the format, not a promise about comprehension.

Microtokens

Repeats become aliases

An atom repeated three times or more becomes a one-token alias. The canonical form, and its hash, do not change.

Canonical and reversible

Same bytes everywhere

The same entry yields the same canonical bytes across runtimes. HCORTEX is a rendering, not a second source.

Editor tooling

arqux-cortex-viewer — the format as a working surface.

VS Code extension · v0.4.2 · Apache‑2.0 · VSIX from the repository. Offline-first: zero telemetry, zero network calls.

See the document

Live HCORTEX preview

Sections, tables and the glossary render as you type, with the canonical sha256 and a loss counter. PlantUML and Mermaid render locally as SVG.

Edit with guardrails

Loss-guarded editing

Table edits round-trip through the codec and abort on any loss. Errors carry codec codes at the exact line and column.

Beyond one editor

cortex-ls

One stdio language server for diagnostics, completion, rename and corpus validation. VS Code connects today; other editors can attach.

Requires codec-cortex ≥ 1.0.1; the toolchain resolves Rust → Go → Python → Node. Minimal install: pip install codec-cortex. Extension source, changelog and security notes →

Why not just YAML/JSON/Markdown? ›
They can hold data, but they have no idea-level unit, no local-glossary layer and no canonical expansion — density and reversibility become accidents of how you write them, not properties of the format. CORTEX makes them contract. Limits still apply: density is a representation property (bytes · tokens · repetition), not a comprehension claim; token advantages publish with a neutral corpus and declared limits, per the project charter. Platform direction

Known limits · Framework v1.0.0

Read before adoption

Review the limits before you adopt it.

Distribution lags the code.

pip install arqux publishes 0.9.0; v1.0.0 installs from the repository until it reaches PyPI, and the GitHub releases page still lists 0.9.0.

Check PyPI ↗
One workspace, no hosted coordination.

Coordination is journal-based (push-delta / pull-policy, optimistic lock → ERR_CONFLICT_VERSION). No multi-tenant service ships, and drift surfaces when you run sync-harnesses or drift-check — not from a background watcher.

Execution is bounded by declaration.

task.run executes only declared [exec:action] steps under a bound session; unbound calls are rejected with UNBOUND_SESSION. It is not a general shell.

Evidence is checkable, not an audit.

Sealed manifests and cortex-verify detect tampering (ERR_HASH_MISMATCH). Hashes are not signatures, and none of it replaces an independent audit. evidence export blocks private fields unless --redact-private or --allow-raw is explicit.

The codec certificate has scope.

The published certificate covers codec_cortex 1.0.0 behaviour — idempotence, render parity and runtime parity. It says nothing about Framework behaviour or about whether a model understands the format.

Open certificate ↗
Harness behaviour is external.

ArqUX renders each native file from one kernel, but how an application reads it belongs to that application. The projections carry the same source_hash; they do not control the app.

Limits are recorded per version in the changelog; this card reflects the v1.0.0 entry. Read the changelog ↗

Trust and limits

Enforced by code, or dependent on the agent.

Three kinds of control. ArqUX should make the difference visible.

01

Applied by code

Handler permissions and validation, only where the release implements and tests them.

02

Read by the agent

Instruction files shape an agent's work. They do not guarantee obedience.

03

Owned by the team

Review, approval and key handling follow the workflow your team documents.

A hash can detect a mismatch against a trusted reference. It is not a signature or an independent audit.

Copies are not kept in sync in the background. Files rendered by sync-harnesses are projections; independent copies can become outdated or diverge until re-rendered.
