src

What "from source" means here

pip install -e . installs the revision you checked out, in editable mode, inside the virtual environment: it reproduces exactly the inspected 1.0.0 source for this test. It is not a PyPI release and it does not update itself when the repository moves on.

Requirements: Python 3.10 or newer (verified on 3.11.12), Git, a POSIX shell and a directory you can write to.

The 2026-11-20 check found 0.9.0 on PyPI. Use this source revision to reproduce the 1.0.0 test.

Why we pin a revision

The commit 390333913e0f071a89241187f36cc90289e7e043 corresponds to version 1.0.0 in the public repository's pyproject.toml. Checking it out reproduces the inspected source; it is not a package publication and does not guarantee the repository HEAD is identical.

python3 -m venv .venv creates a virtual environment inside the cloned folder and source .venv/bin/activate activates it in POSIX shells; on other shells use their own activator. Keep the environment active — or prefix commands with .venv/bin/ — when running the first task.

If PyPI publishes 1.0.0 and it is verified, this section will show that command as the primary channel. Check the PyPI JSON API ↗ before assuming it is already published.

Create the first task

YOUR FIRST RESULT

A file created. A task completed. A trail you can inspect.

The CLI test runs a task and keeps an inspectable result. You can reproduce it and compare the evidence.

The result

  • Filefirst-task.txt = hello-from-arqux
  • TaskT-001 · done
  • EvidenceSHA-256 hash and PULSE event

How to run it

  • PrepareCreate the arqux-first folder, activate the environment from the previous step and set ARQUX_EXECUTION_KEY for the whole session.
  • Declarearqux init, project Demo, cycle CYCLE-01, session context and the task to create.
  • ExecuteRun T-001 and complete it with the file hash as evidence.
  • VerifyRead first-task.txt and compare the result with the recorded evidence.

The timelog may show an operation pending recording; the task in this run finished in done.

View and copy all commands

The full sequence

mkdir arqux-first && cd arqux-first
export ARQUX_EXECUTION_KEY=first-task-demo
arqux init
arqux project init name=Demo
arqux cycle create name=CYCLE-01 description="First governed task"
arqux call session.context_set project=Demo scope=CYCLE-01
arqux call task.create content='$1:{obj:"Create a first governed artifact",proc:["Write first-task.txt [exec:write_file path=first-task.txt content=hello-from-arqux]"],ac:["first-task.txt contains hello-from-arqux"],complexity:"simple"}'
arqux call task.run task_id=T-001
arqux call task.complete task_id=T-001 evidence="first-task.txt sha256=$(sha256sum first-task.txt | cut -d' ' -f1)"
cat first-task.txt
Requires a POSIX shell (export, sha256sum, $(...)), ArqUX 1.0.0 installed and a writable directory. Run the commands exactly as shown, in order; the execution key must be the same across all of them.

Connect my agent

CONNECT YOUR ENVIRONMENT

Your agent can receive the project's governance references through two paths.

Start with instruction files. If your client supports MCP, you can also configure access to ArqUX operations.

A · My agent reads files

Generate instructions for available conventions and confirm which file your tool reads.

cd /path/to/workspace
arqux init
arqux sync-harnesses
  • What you doRun arqux init and arqux sync-harnesses inside the project root.
  • What you getFiles such as AGENTS.md, CLAUDE.md, GEMINI.md and .opencode/instructions.md, following the applicable convention.
  • What you checkVerify your client actually reads the right file; run arqux drift-check if you want to detect differences from the source.
Each harness reads its own native file (AGENTS.md is the generic one). ArqUX does not run the sync for you.

B · My client supports MCP

Configure the stdio server and verify a read-only operation before continuing.

cd /path/to/workspace
arqux serve
  • What you doStart arqux serve in the project and configure the connection in your client.
  • What you getAccess to the operations the server exposes, within the permissions and limits the code implements.
  • What you checkRun a read operation such as workspace.status before trusting it with other actions.
One workspace per process. ArqUX does not configure clients automatically; if your harness offers no MCP, route A file adhesion still applies.
