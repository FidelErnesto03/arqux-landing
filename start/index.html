Get started

Your first governed project, with ArqUX 1.0.0.

Install, create a workspace, run a task and check what was recorded. The target version is 1.0.0 and today's verified channel is installing from the public repository, pinned to a specific commit.

You need Python 3.11 or newer, git, a POSIX shell and a writable working directory. By the end you will have a first-task.txt file, task T-001 closed and hash evidence you can review.

Installation

One verified channel: the pinned public source.

PyPI does not publish ArqUX 1.0.0 yet, so the tested path is installing from the repository at the exact verified commit. Run the commands, activate the environment and check that arqux --version answers arqux 1.0.0.

A

Install from source · verified channel

Clone the repository, check out the pinned commit, create a virtual environment and install editable. Requirements: Python 3.11 or newer, git, a POSIX shell and a directory you can write to.

git clone https://github.com/FidelErnesto03/arqux
cd arqux
git checkout 390333913e0f071a89241187f36cc90289e7e043
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
arqux --version

Verified 2026-11-20 · Linux · Python 3.11.12 · arqux --version output: arqux 1.0.0. The pin reproduces the inspected 1.0.0 source; it is not a PyPI publication.

0.9

What PyPI serves today

The public index currently serves 0.9.0. Running pip install arqux today does not install 1.0.0: it resolves to the latest published release, still 0.9.0. That is why this page does not offer it as a path to 1.0.0; when the 1.0.0 package is published and verified, this section will show that command.

Observed 2026-11-20 via the PyPI JSON API ↗.

Technical detail

The commit 390333913e0f071a89241187f36cc90289e7e043 corresponds to version 1.0.0 in the public repository's pyproject.toml. git checkout on that commit reproduces the inspected source; it is not a package publication and does not guarantee the repository HEAD is identical.

python3 -m venv .venv creates a virtual environment inside the cloned folder and source .venv/bin/activate activates it in POSIX shells; on other shells use their own activator. Keep the environment active — or prefix commands with .venv/bin/ — when running the first task.

If PyPI publishes 1.0.0 and it is verified, this section will show that command as the primary channel.

Verified end to end

A first task, with results and limits you can check.

The sequence runs the CLI path on an empty folder with ArqUX 1.0.0 installed from the pinned source; it invokes no model and no agent. Linux · Python 3.11.12 · commit 3903339 · verified 2026-11-20 · CLI only, no agent identity.

What you'll do

  • PrepareCreate the arqux-first folder, activate the environment from the previous step and set ARQUX_EXECUTION_KEY for the whole session.
  • Declarearqux init, project Demo, cycle CYCLE-01, session context and the task to create.
  • Run and closeRun T-001 and complete it with the file hash as evidence.
  • CheckRead first-task.txt and compare the result with the recorded evidence.

What you'll see

  • Artifactfirst-task.txt contains hello-from-arqux.
  • TaskT-001 ends done; the PULSE event is SES001-E0002.
  • WarningThe timelog leaves a notice in pending state: it is detailed under evidence.

What it does not prove: model reasoning, the behavior of a specific harness, or that every client reproduces the same timelog lifecycle. It is the pure CLI path.

The full sequence

mkdir arqux-first && cd arqux-first
export ARQUX_EXECUTION_KEY=first-task-demo
arqux init
arqux project init name=Demo
arqux cycle create name=CYCLE-01 description="First governed task"
arqux call session.context_set project=Demo scope=CYCLE-01
arqux call task.create content='$1:{obj:"Create a first governed artifact",proc:["Write first-task.txt [exec:write_file path=first-task.txt content=hello-from-arqux]"],ac:["first-task.txt contains hello-from-arqux"],complexity:"simple"}'
arqux call task.run task_id=T-001
arqux call task.complete task_id=T-001 evidence="first-task.txt sha256=$(sha256sum first-task.txt | cut -d' ' -f1)"
cat first-task.txt
Requires a POSIX shell (export, sha256sum, $(...)), ArqUX 1.0.0 installed and a writable directory. Run the commands exactly as shown, in order; the execution key must be the same across all of them.

Recorded evidence

  • Hashsha256:4340d832667bc0d34c6f232e7858cdf0ae070ac942e6c53e755f224b8ee9c594 of first-task.txt.
  • Task and eventT-001 in done; PULSE event SES001-E0002; pin 390333913e0f071a89241187f36cc90289e7e043.
  • To inspectThe timelog record lives at .arqux/timelog/SES001_*.cortex.

Warning and scope

  • Real CLI outputoperation 'task:T-001' is not recorded in this timelog — pending state.
  • What it coversThe artifact and the evidence are complete; the warning concerns timelog coverage, not the task status.
  • ScopeVerified via CLI only, with no agent identity. Full limits at Trust → Limits.

The verification is pinned to commit 3903339; if the repository HEAD moves on, re-run the sequence after updating the pin.

Connect your agent

Two adhesion routes: instruction files and MCP operations.

ArqUX adheres to your environment in two complementary ways: instruction files the harness reads natively, and MCP operations when the client allows them. Neither replaces the other, and client behavior stays outside ArqUX.

Route 1 · Project instructions

After arqux init, arqux sync-harnesses projects the kernel into files each harness reads natively: AGENTS.md, CLAUDE.md, GEMINI.md and .opencode/instructions.md.

cd /path/to/workspace
arqux init
arqux sync-harnesses
Run it inside the project root. Each harness reads its own native file (AGENTS.md is the generic one); ArqUX does not run the sync for you and the files' presence alone does not guarantee the agent obeys them.

Route 2 · MCP operations (stdio)

arqux serve exposes the governance handlers over stdio to MCP-capable clients. Configuration is external: each client defines its own.

cd /path/to/workspace
arqux serve
One workspace per process. After connecting, check access with a read-only call (e.g. workspace.status); ArqUX does not configure clients automatically. If your harness offers no MCP, route 1 file adhesion still applies.Claude Desktop example — adapt cwd to your workspace:
{
  "mcpServers": {
    "arqux": {
      "command": "arqux",
      "args": ["serve"],
      "cwd": "/path/to/workspace"
    }
  }
}

Matrix and scope

The compatibility matrix details adhesion per environment: file projection, MCP where the client allows it, and the verification status of each one. Environments declared by the project: HermesAgent, OpenCode, Command Code, Codex, Devin, Antigravity, Claude Code, Qwen Coder and Kiro, among others; appearing there does not imply automatic MCP setup or an identical integration level.

Harness behavior and client configuration are external to ArqUX. Sources at 3903339: harness.py · _TARGETS · deployment guide ↗.
