Codec-CORTEX

How information is represented and preserved.

CORTEX is the mandatory memory format of ArqUX v1.0.0: dense for machines, readable as HCORTEX for people, and validated with loss==0 before every write. The demo below is a simulation and does not execute the codec.

One idea, two surfaces, one source — type and both renderings update. The real codec validates with loss==0; this demo shows the pairing only.

Signal, not filler

One idea per line

Norms live in typed ideas, not in prose. Density is a property of the format, not a promise about comprehension.

Microtokens

Repeats become aliases

An atom repeated three times or more becomes a one-token alias. The canonical form, and its hash, do not change.

Canonical and reversible

Same bytes everywhere

The same entry yields the same canonical bytes across runtimes. HCORTEX is a rendering, not a second source.

Editor tooling

arqux-cortex-viewer — the format as a working surface.

VS Code extension · v0.4.2 · Apache‑2.0 · VSIX from the repository. Offline-first: zero telemetry, zero network calls.

See the document

Live HCORTEX preview

Sections, tables and the glossary render as you type, with the canonical sha256 and a loss counter. PlantUML and Mermaid render locally as SVG.

Edit with guardrails

Loss-guarded editing

Table edits round-trip through the codec and abort on any loss. Errors carry codec codes at the exact line and column.

Beyond one editor

cortex-ls

One stdio language server for diagnostics, completion, rename and corpus validation. VS Code connects today; other editors can attach.

Requires codec-cortex ≥ 1.0.1; the toolchain resolves Rust → Go → Python → Node. Minimal install: pip install codec-cortex. Extension source, changelog and security notes →

Why not just YAML/JSON/Markdown? ›
They can hold data, but they have no idea-level unit, no local-glossary layer and no canonical expansion — density and reversibility become accidents of how you write them, not properties of the format. CORTEX makes them contract. Limits still apply: density is a representation property (bytes · tokens · repetition), not a comprehension claim; token advantages publish with a neutral corpus and declared limits, per the project charter.
