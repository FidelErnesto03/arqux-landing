Trust and limits

Three responsibilities, three limits.

A control is only as strong as the layer that applies it. Each card states the operative question and who answers for it.

01

What does the code enforce or validate?

Handler permissions and input validation, only on the routes where release 1.0.0 implements and tests them — for example, task.run executes only declared actions under a bound session. Responsible layer: the framework code. Your action: check in the evidence which routes are covered before relying on a control.

02

What does the agent interpret?

Instruction files — AGENTS.md and the native projections that sync-harnesses renders for each harness — guide the agent's work, but they do not guarantee obedience: it depends on the application reading and following them. Responsible layer: your tool and the model. Your action: review which files your agent loads and do not delegate to instructions a rule that code could enforce; copies are not kept in sync in the background — see the compatibility matrix.

03

What does the team own?

Credentials, approval of actions, review of evidence and the decision to adopt remain human responsibilities: the agent can propose, not accept on your behalf. Responsible layer: your team. Your action: define who approves, who reviews and what evidence is required before accepting work.

A hash verifies consistency against a trusted reference; it does not prove identity or constitute an independent audit.

Known limits · Framework v1.0.0 · verified 2026-11-20

Read before adoption

Limits you should know before adopting ArqUX.

1 · Version and distribution

Limit: PyPI currently serves arqux 0.9.0; ArqUX 1.0.0 lives in the source, at the pinned commit, until it is published to the index. Consequence: pip install arqux installs 0.9.0 — a different version from the audited one; the claims on this page do not apply to it. Verify: install from the pinned source or check arqux --version; look at PyPI again before adopting.

Install channelsPyPI ↗
2 · Governance: code vs. instructions

Limit: code enforces only what the release implements and tests — permissions, validation and bounded execution; everything else lives in instruction files the agent may read or ignore. Consequence: a rule written only in AGENTS.md or in a projection depends on the harness's obedience: it bounds intent, not capability. Verify: tell code-enforced controls apart from instruction-level rules; keep in handlers what must be impossible to skip.

Evidence rowsHANDLERS.md ↗
3 · Coordination

Limit: coordination between workspaces is a local journal (push-delta/pull-policy, optimistic lock → ERR_CONFLICT_VERSION); there is no hosted multi-tenant service in 1.0.0 — Platform is direction. Consequence: governing several teams or machines requires your own process, and drift only surfaces when you run sync-harnesses or drift-check. Verify: the journal orders push and pull explicitly; run drift-check after editing projections.

journal.py ↗cli.py ↗
4 · Integrity and evidence

Limit: sealed manifests and cortex-verify detect tampering against a trusted reference (ERR_HASH_MISMATCH); evidence export blocks private fields unless a flag is explicit; the codec certificate covers only the codec — its scope is detailed in the evidence section. Consequence: you can detect that your artifacts changed, but there is no independent audit, signature or security certification: a hash does not prove the publisher's identity. Verify: run cortex-verify on exports and review the documented threat model.

Certificate scopeSECURITY.md ↗THREAT_MODEL.md ↗
5 · Integration

Limit: harness behaviour is external: ArqUX renders four native targets (AGENTS.md, CLAUDE.md, GEMINI.md, .opencode/instructions.md) from one kernel, but how each application reads them belongs to that application; adhesion declared on nine harnesses is project-reported, with a test sheet pending. Consequence: "works with my agent" depends on your tool honouring the files and the MCP you configure; projections do not sync by themselves. Verify: check the compatibility matrix; re-render with sync-harnesses and check drift.
