Trust and limits

Three responsibilities, three limits.

A control is only as strong as the layer that applies it.

01

Applied by code

Handler permissions and validation, only where the release implements and tests them.

02

Read by the agent

Instruction files shape an agent's work. They do not guarantee obedience.

03

Owned by the team

Review, approval and key handling follow the workflow your team documents.

A hash can detect a mismatch against a trusted reference. It is not a signature or an independent audit.

Copies are not kept in sync in the background. Files rendered by sync-harnesses are projections; independent copies can become outdated or diverge until re-rendered.

Known limits · Framework v1.0.0

Read before adoption

Review the limits before you adopt it.

Distribution lags the code.

pip install arqux publishes 0.9.0; v1.0.0 installs from the repository. There is no GitHub release artifact for either version yet.

Check PyPI ↗
One workspace, no hosted coordination.

Coordination is journal-based (push-delta / pull-policy, optimistic lock → ERR_CONFLICT_VERSION). No multi-tenant service ships, and drift surfaces when you run sync-harnesses or drift-check — not from a background watcher.

Execution is bounded by declaration.

task.run executes only declared [exec:action] steps under a bound session; unbound calls are rejected with UNBOUND_SESSION. It is not a general shell.

Evidence is checkable, not an audit.

Sealed manifests and cortex-verify detect tampering (ERR_HASH_MISMATCH). They do not replace an independent audit. evidence export blocks private fields unless --redact-private or --allow-raw is explicit.

The codec certificate has scope.

The published certificate covers codec_cortex 1.0.2-rc.1 behaviour — idempotence, render parity and runtime parity. It says nothing about Framework behaviour or about whether a model understands the format.

Open certificate ↗
Harness behaviour is external.

ArqUX renders each native file from one kernel, but how an application reads it belongs to that application. The projections carry the same source_hash; they do not control the app.

Limits are recorded per version in the changelog; this card reflects the v1.0.0 entry. Read the changelog ↗
