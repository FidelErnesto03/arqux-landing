Three responsibilities

The system enforces. Agents interpret. You decide.

ArqUX governs what its code can verify. Instructions guide the agent. You retain approval and responsibility for the outcome.

Installed version

The verified source is 1.0.0; PyPI served 0.9.0 at the last documented check.

Code and instructions

A file guides an agent; only implemented controls can restrict operations.

See consequence, check, and source

Practical consequence: the code enforces only what the release implements and tests — permissions, validation and bounded execution; everything else lives in instruction files the agent may read or ignore. A rule written only in AGENTS.md or in a projection depends on the harness's obedience: it bounds intent, not capability.

How to verify: tell code-enforced controls apart from instruction-level rules; keep in handlers what must be impossible to skip.

Workspace coordination

The journal exchanges changes explicitly; 1.0.0 does not include a hosted multiuser service.

See consequence, check, and source

Practical consequence: governing several projects or machines requires your own process, and drift only surfaces when you run sync-harnesses or drift-check; there is no hosted multi-tenant service in 1.0.0 — Platform is direction.

How to verify: the journal orders push and pull explicitly with optimistic locking (ERR_CONFLICT_VERSION); run drift-check after editing projections.

Integrity and authorship

A hash verifies changes; Ed25519 signatures require specific actions and keys.

See consequence, check, and source

Practical consequence: SHA-256 manifests can detect changes against trusted references; they do not prove who produced a document on their own. ArqUX 1.0.0 also provides optional Ed25519 signing and verification for .cortex documents. Signatures must be created and verified with properly managed keys; they are not applied automatically to all evidence and do not amount to an independent audit or security certification.

How to verify: sealed manifests and cortex-verify detect tampering against a trusted reference (ERR_HASH_MISMATCH); evidence export blocks private fields unless a flag is explicit. Run cortex-verify on exports and review the documented threat model.

Agent integration

Confirm which instructions your client loads and whether it supports MCP before relying on that connection.

See consequence, check, and source

Practical consequence: harness behaviour is external — ArqUX renders four native targets (AGENTS.md, CLAUDE.md, GEMINI.md, .opencode/instructions.md) from one kernel, but how each application reads them belongs to that application; adhesion declared on nine harnesses is project-reported, with a test sheet pending. "Works with my agent" depends on your tool honouring the files and the MCP you configure; projections do not sync by themselves.

How to verify: check the compatibility matrix; re-render with sync-harnesses and check drift.
