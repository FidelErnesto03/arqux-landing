La tarea

Un proyecto. Múltiples agentes. Gobierno unificado.

Defines tu proyecto con ayuda de un agente de IA. Cambia de agente o herramienta y continúa con los objetivos, lineamientos y contexto de tu proyecto. Con cada tarea, ese contexto puede enriquecerse con nuevas decisiones y aprendizajes.

  1. 01DefinirAgregar recuperación de contraseña. Condición: no modificar la autenticación existente.

    condición · aceptación

  2. 02TrabajarEl agente A comprueba la condición, propone la solución, implementa el envío y registra decisiones, evidencia y un checkpoint.

    condición · contexto · evidencia

  3. 03RetomarEl agente B recibe el avance y la misma condición, y completa la validación del enlace.

    avance · condición · sesión

  4. 04Revisar y aprenderCompruebas el resultado frente a las condiciones y revisas las pruebas. Las decisiones y aprendizajes relevantes pueden incorporarse para futuras tareas.

    condición · pruebas · aprendizaje

Inicio rápido

Tres comandos, un directorio.

Sin servidor ni clave de API. Instala, inicializa un workspace gobernado y genera los archivos de cada aplicación de agente. Tus lineamientos y contexto quedan en archivos planos y portables.

Terminal
$ pip install arqux
$ arqux init
$ arqux sync-harnesses
$ pip install arqux
$ arqux quickstart
$ arqux sync-harnesses

Ambas rutas forman parte de v1.0.0: init inicializa el espacio de trabajo; quickstart ejecuta el onboarding interactivo para un agente nuevo. Confirma el comportamiento con la versión que instales.

Cada línea es una idea.

Una idea, dos superficies, una fuente — escribe y las dos representaciones se actualizan. El codec real valida con loss==0; esta demo muestra solo el emparejamiento.

Señal, no relleno

Una idea por línea

Las normas viven en ideas tipadas, no en prosa. La densidad es una propiedad del formato, no una promesa de comprensión.

Microtokens

Las repeticiones se vuelven alias

Un átomo repetido tres veces o más se convierte en un alias de un token. La forma canónica, y su hash, no cambian.

Canónico y reversible

Mismos bytes en todas partes

La misma entrada produce los mismos bytes canónicos en todos los runtimes. HCORTEX es una representación, no una segunda fuente.

Edición con guarda de pérdida

Las ediciones de tabla pasan por el codec y se abortan ante cualquier pérdida. Los errores llevan códigos del codec en la línea y columna exactas.

Más allá de un editor

cortex-ls

Un servidor de lenguaje stdio para diagnósticos, autocompletado, renombrado y validación de corpus. VS Code se conecta hoy; otros editores pueden conectarse.

Requiere codec-cortex ≥ 1.0.1; la cadena de herramientas resuelve Rust → Go → Python → Node. Instalación mínima: pip install codec-cortex. Código de la extensión, changelog y notas de seguridad →

¿Por qué no solo YAML/JSON/Markdown? ›
Pueden guardar datos, pero no tienen unidad de idea, ni capa de glosario local, ni expansión canónica — la densidad y la reversibilidad se vuelven accidentes de cómo escribes, no propiedades del formato. CORTEX las convierte en contrato. Los límites siguen aplicando: la densidad es una propiedad de la representación (bytes · tokens · repetición), no una afirmación de comprensión; las ventajas de tokens se publican con corpus neutral y límites declarados, según el charter del proyecto. Leer antes de adoptar

Revisa los límites antes de adoptarlo.

La distribución va por detrás del código.

pip install arqux publica 0.9.0; v1.0.0 se instala desde el repositorio hasta que llegue a PyPI, y la página de releases de GitHub todavía lista 0.9.0.

Ver PyPI ↗
Un espacio de trabajo, sin coordinación alojada.

La coordinación es por journal (push-delta / pull-policy, bloqueo optimista → ERR_CONFLICT_VERSION). No hay servicio multi-tenant, y la deriva aparece al ejecutar sync-harnesses o drift-check — no hay vigilante en segundo plano.

La ejecución está acotada por declaración.

task.run ejecuta solo pasos declarados [exec:action] bajo sesión vinculada; las llamadas sin vínculo se rechazan con UNBOUND_SESSION. No es un shell general.

La evidencia es comprobable, no una auditoría.

Los manifiestos sellados y cortex-verify detectan manipulación (ERR_HASH_MISMATCH). Los hashes no son firmas y nada de esto sustituye una auditoría independiente. evidence export bloquea campos privados salvo --redact-private o --allow-raw explícitos.

El certificado del codec tiene alcance.

El certificado publicado cubre el comportamiento de codec_cortex 1.0.0 — idempotencia, paridad de render y paridad entre runtimes. No dice nada del comportamiento del Framework ni de si un modelo entiende el formato.

Abrir certificado ↗
El comportamiento del harness es externo.

ArqUX genera cada archivo nativo desde un kernel, pero cómo lo lee una aplicación es asunto de esa aplicación. Las proyecciones llevan el mismo source_hash; no controlan la app.

Los límites se registran por versión en el changelog; esta tarjeta refleja la entrada de v1.0.0. Leer el changelog ↗

Confianza y límites

Lo que impone el código, y lo que depende del agente.

Tres tipos de control. ArqUX debe hacer visible la diferencia.

01

Aplicado por código

Permisos de handlers y validación, solo donde la versión los implementa y prueba.

02

Leído por el agente

Los archivos de instrucciones moldean el trabajo del agente. No garantizan obediencia.

03

Responsabilidad del equipo

Revisión, aprobación y gestión de claves siguen el flujo que tu equipo documenta.

Un hash puede detectar una discrepancia frente a una referencia confiable. No es una firma ni una auditoría independiente.

Las copias no se sincronizan en segundo plano. Los archivos generados por sync-harnesses son proyecciones; las copias independientes pueden quedar desactualizadas o divergir hasta volver a generarse.

Preguntas que investigamos, no funciones.

La Platform alojada está en desarrollo. Evidencia firmada, exportaciones para auditoría y permisos por workspace son preguntas abiertas en evaluación.
