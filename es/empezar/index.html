Crea una tarea. Comprueba el resultado.

Instala ArqUX 1.0.0, ejecuta una primera tarea por CLI y revisa el archivo y las evidencias que produce.

Esta primera prueba utiliza el CLI, sin agente. Después podrás conectar tu herramienta.

Qué vas a conseguir

  • Tarea completadaT-001 termina en estado done.

Qué significa «desde la fuente» aquí

pip install -e . instala la revisión que descargaste, en modo editable, dentro del entorno virtual: reproduce exactamente la fuente 1.0.0 inspeccionada para esta prueba. No es una publicación de PyPI ni se actualiza sola cuando el repositorio avanza.

Requisitos: Python 3.10 o superior (verificado en 3.11.12), Git, un shell POSIX y un directorio con permisos de escritura.

La verificación del 20-11-2026 encontró PyPI en 0.9.0. Usa esta revisión fuente para reproducir la prueba 1.0.0.

Por qué fijamos una revisión

El commit 390333913e0f071a89241187f36cc90289e7e043 corresponde a la versión 1.0.0 del pyproject.toml en el repositorio público. Situarse en ese commit reproduce la fuente inspeccionada; no es una publicación de paquete ni garantiza que el HEAD del repositorio sea idéntico.

python3 -m venv .venv crea un entorno virtual dentro de la carpeta clonada y source .venv/bin/activate lo activa en shells POSIX; en otros shells usa su propio activador. Mantén el entorno activado —o antepone .venv/bin/ a los comandos— al ejecutar la primera tarea.

Si PyPI publica 1.0.0 y se verifica, esta sección pasará a mostrar ese comando como canal principal. Consulta la API JSON de PyPI ↗ antes de asumir que ya está publicada.

Crear la primera tarea

TU PRIMER RESULTADO

Un archivo creado. Una tarea cerrada. Un rastro que puedes comprobar.

La prueba ejecuta una tarea por CLI y conserva un resultado inspeccionable. Puedes reproducirla y contrastar sus evidencias.

El resultado

  • Archivofirst-task.txt = hello-from-arqux
  • TareaT-001 · done
  • EvidenciaHash SHA-256 y evento PULSE

Cómo ejecutarla

  • PrepararCrea la carpeta arqux-first, activa el entorno del paso anterior y fija ARQUX_EXECUTION_KEY para toda la sesión.
  • Declarararqux init, proyecto Demo, ciclo CYCLE-01, contexto de sesión y la tarea a crear.
  • EjecutarCorre T-001 y la completas con la evidencia del hash del archivo.
  • ComprobarLee first-task.txt y contrasta el resultado con la evidencia registrada.

El timelog puede mostrar una operación en estado pendiente de registro; la tarea de esta ejecución terminó en done.

Ver y copiar todos los comandos

La secuencia completa

mkdir arqux-first && cd arqux-first
export ARQUX_EXECUTION_KEY=first-task-demo
arqux init
arqux project init name=Demo
arqux cycle create name=CYCLE-01 description="First governed task"
arqux call session.context_set project=Demo scope=CYCLE-01
arqux call task.create content='$1:{obj:"Create a first governed artifact",proc:["Write first-task.txt [exec:write_file path=first-task.txt content=hello-from-arqux]"],ac:["first-task.txt contains hello-from-arqux"],complexity:"simple"}'
arqux call task.run task_id=T-001
arqux call task.complete task_id=T-001 evidence="first-task.txt sha256=$(sha256sum first-task.txt | cut -d' ' -f1)"
cat first-task.txt
Requiere un shell POSIX (export, sha256sum, $(...)), ArqUX 1.0.0 instalado y un directorio escribible. Ejecuta los comandos tal cual, en orden; la clave de ejecución debe ser la misma en todos.

Conectar mi agente

CONECTA TU ENTORNO

Tu agente puede recibir las referencias de gobierno del proyecto por dos vías.

Empieza por archivos de instrucciones. Si tu cliente admite MCP, también puedes configurar el acceso a operaciones de ArqUX.

A · Mi agente lee archivos

Genera instrucciones para las convenciones disponibles y comprueba cuál lee tu herramienta.

cd /path/to/workspace
arqux init
arqux sync-harnesses
  • Qué hacesEjecuta arqux init y arqux sync-harnesses dentro de la raíz del proyecto.
  • Qué obtieneArchivos como AGENTS.md, CLAUDE.md, GEMINI.md y .opencode/instructions.md, según la convención aplicable.
  • Qué compruebasVerifica que tu cliente lea realmente el archivo correcto; ejecuta arqux drift-check si quieres detectar diferencias respecto a la fuente.
Cada harness lee su archivo nativo (AGENTS.md es el genérico). ArqUX no ejecuta la sincronización por ti.

B · Mi cliente admite MCP

Configura el servidor stdio y comprueba una operación de lectura antes de continuar.

cd /path/to/workspace
arqux serve
  • Qué hacesInicia arqux serve en el proyecto y configura la conexión en tu cliente.
  • Qué obtieneAcceso a las operaciones que expone el servidor, dentro de los permisos y límites que implementa el código.
  • Qué compruebasRealiza una operación de lectura como workspace.status antes de confiarle otras acciones.
Un workspace por proceso. ArqUX no configura clientes automáticamente; si tu harness no ofrece MCP, la adhesión por archivos de la ruta A sigue siendo válida.
Ver un ejemplo de configuración MCP
Ejemplo para Claude Desktop — adapta cwd a tu workspace:
{
  "mcpServers": {
    "arqux": {
      "command": "arqux",
      "args": ["serve"],
      "cwd": "/path/to/workspace"
    }
  }
}

Compatibilidad por entorno

La matriz de compatibilidad es la referencia canónica: cuatro convenciones de proyección de archivos implementadas, MCP cuando el cliente lo permite y el estado de verificación de cada entorno. Figurar ahí no implica configuración MCP automática ni un nivel de integración idéntico; el comportamiento del harness y la configuración del cliente permanecen fuera de ArqUX.

Fuentes en 3903339: harness.py · _TARGETS · guía de despliegue ↗.

ArqUX no configura todos los clientes automáticamente, y un modelo no obedece las instrucciones solo porque los archivos existan.
